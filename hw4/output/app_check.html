Campus Customs — site test

Six checks run against the live site, driven end to end in Chrome by frontend/scripts/capture_app_check.mjs. Every screenshot below is one of those runs.

Front end Vite + React + TypeScript, http://localhost:5173
Back end FastAPI, uvicorn main:app --reload --port 8000
Agent PydanticAI, gpt-4o-mini via Portkey
Database data/campus_customs.db — 102 products, 612 stock rows

Check 2 — requiredDynamic search-result cards after a category question

This is the Problem 7 contract working: the agent called search_products, returned structured matches in ShopReply.products, and the front end drew them with the same tile component the grid uses. Every card was re-read from the database by product_id before rendering, and clicking one opens that item’s single-item page.

Check 3 — requiredUsability feature: filters, sort and skeletons

Improvement 1 from usability.md. The search is debounced by 220 ms and the grid shows shimmering skeleton tiles while the request is in flight, so a 102-product catalogue stays navigable and the page never flashes blank. Category, sort and “in stock only” all narrow the same result set.

Check 4Single-item page with real per-size stock

XS, M and XXL are struck through and unclickable because their quantity is zero; S is selected and the line under the row reads “5 in stock in S.” This is the page that both a grid tile and a chat card open, and it is where the agent gets its page context from.

The transcript above the new question was re-read from chat_messages after the reload, not held in the browser, and the agent answers “You said you wear a large (L).” The header shows “Signed in as Test”, which is the customer identity the agent receives in its deps.

Check 6Storefront home

The nav links to Home, Products, About Us, Log in and Create account, and the chat launcher sits in the bottom right on every page.
